**Bug 1 (regime_alloc_backtest.py:140):** charged 30bps per one-way regime flip via `flips=regime_signal.diff().abs(); cost=-flips*30bps`. A flip is one-way (buy OR sell the basket), so an OFF->ON->OFF cycle = 2 flips = 60bps, but the project convention (--cost-bps in d1_tsmom, d1_trend, coint) is 30bps = full ROUND-TRIP. **Bug 2 (coint_arb_backtest.py:163):** `cost=(bps/1e4)*(xau_entry+xau_exit + beta*(xag_entry+xag_exit))` charged 30bps on BOTH entry and exit notional = 2x its own docstring (line 30: cost=(bps/1e4)*(1+beta) per $1 XAU, i.e. once on entry = the full RT) and 2x project convention.

**FIX both:** regime-alloc -> replaced flip-only cost with a proper month-by-month weight-tracking turnover model: one-way turnover = 0.5*sum|Delta_w_all| (cash leg = residual making weights sum to 1), cost = (cost_bps/2/10000)*turnover (15bps one-way rate).
